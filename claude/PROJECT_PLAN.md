# 의류 MD 채용 브리핑 프로젝트

친구의 취업 준비(의류 MD 직무)를 돕기 위해, 여러 채용 사이트의 공고를 자동으로 모아서 매일 보여주는 개인용 웹페이지를 만드는 프로젝트.

## 1. 목적 / 대상

- **목적**: 친구가 매일 여러 채용 사이트를 직접 돌아다니지 않아도, 지원할 만한 회사와 그 회사들이 요구하는 자격요건/우대사항을 한 곳에서 확인하게 하는 것
- **대상 사용자**: 친구 1명 (비개발자, 링크만 열어서 봄)
- **성격**: 개인적/비상업적 용도. 재판매·재배포 없음

## 2. 검색 조건

- **직무 키워드**: 의류 MD (기본), 패션 MD, 의류기획MD, 패션 온라인MD
- **지역**: 서울, 경기도만
- **그 외 조건(연차, 학력, 연봉 등)**: 제한 없음

## 3. 수집하려는 정보

- 회사명
- 공고 제목 / 직무
- 담당업무
- 자격요건
- 우대사항
- 근무지역
- 급여, 마감일, 고용형태 등 기타 정보
- (트랙 B) 위 항목들을 요약 없이 회사별 원문 그대로 데이터베이스화 — 자동 집계/요약은 하지 않고, 필요할 때 그 데이터를 보고 별도로 분석 요청

## 4. 데이터 소스 현황

| 소스 | 방식 | 상태 | 비고 |
|---|---|---|---|
| 사람인 | 공식 Open API | 신청 완료, **승인 대기 중** | 패션MD 카테고리(cat_kewd=2237)로 서울/경기 필터 가능 확인함 |
| 워크넷(공공데이터포털) | 공식 Open API | **미신청** (진행 예정) | work24.go.kr 직접 신청은 사업자등록번호 필요해 개인 불가 → data.go.kr(공공데이터포털) 경로로 신청해야 함 |
| 잡코리아 | 공식 API | 신청함, **승인 가능성 낮음** | API는 "공공기관/학교 전용", 개인은 내부검토 후 불가한 경우多 |
| 잡코리아 | 브라우저로 직접 열람 | 부분적으로 가능 | 검색(1회성, 사람처럼)은 잘 됨. 상세페이지는 회사마다 다름 — 텍스트로 잘 나오는 공고(예: 지오다노)도 있고, 담당업무/소개를 통째로 이미지 배너로 올린 공고(예: 이랜드리테일)도 많아서 이미지는 텍스트 추출이 안 됨. 자동화 신뢰도 낮음 → 보조 소스로만 고려 |
| 패션워크 (fashionwork.co.kr) | 페이지 직접 열람 | **가능** | 직종코드로 영업MD/상품기획/바잉 등 필터, 상세페이지에 자격요건·우대사항 텍스트로 잘 나옴 |
| 패션인잡 (fashioninjob.co.kr) | 페이지 직접 열람 | **가능** | 지역코드+직종코드 필터(상품기획MD/생산MD/바잉MD 등), 패션 특화라 관련 공고 밀도 높음 |
| 잡플래닛 | - | 불가 | 채용정보가 자바스크립트로 늦게 로딩되어 정적 방식으로 안 읽힘 |
| 인크루트 | - | 불가 | robots.txt가 접근 자체를 막아둠 |
| 원티드 | - | 불가 | 접근 시도 시 403 차단 |
| 온엠디 | - | 불가 | 접근 시도 시 403 차단 |

## 5. 왜 API를 우선하는가 (크롤링 대신)

- 사람인·잡코리아 모두 robots.txt로 검색/상세 크롤링을 일부 막아두고, 그 대신 공식 API를 열어둔 구조
- 잡코리아는 과거 무단 크롤링 업체를 상대로 소송(저작권침해금지)해서 승소한 전례 있음
- 크롤링 방식은 마감일 표기 형식 불일치, 동적 로딩, 이미지 배너 등으로 유지보수 부담이 큼 (실제 유사 사이드프로젝트들의 공통적인 어려움으로 확인됨)
- → 가능한 한 공식 API(사람인, 워크넷) 중심으로 가고, 패션워크·패션인잡처럼 구조가 안정적이고 robots.txt로도 막혀있지 않은 곳만 보조로 추가. 잡코리아는 승인되면 API로, 안 되면 최소한으로만 사용

## 6. 작업 범위 재정리 (2가지 트랙)

프로젝트를 두 개의 독립적인 작업으로 나눠서 진행하기로 함.

### 트랙 A — 매일(주기적) 채용공고 리스트업
- 정해진 시각에 자동 실행되어야 하는 건 아니고, 페이지 접속/버튼 클릭 등 트리거가 있을 때마다 최신 공고를 가져와서 보여주는 방식이면 됨. 목표는 "주기적으로 최신 상태 유지"이지 "매일 몇 시 정각"이 아님
- 대상: 사람인 API + 워크넷 API 중심 (승인 대기 중), 패션워크·패션인잡 보완
- 결과물: 친구가 여는 브리핑 웹페이지 (게시된 아티팩트) — "오늘의 맞춤 채용공고"

### 트랙 B — 직무 방향성별 요건 원본 수집 (거의 1회성, 필요시 주 단위 재실행)
- 목적: 동일 직무뿐 아니라 인접/유사 직무까지 넓혀서, 각 공고의 자격요건·우대사항·업무내용 등을 **요약하지 않고 원문 그대로** 회사별 한 행씩 데이터베이스화
- 범위: 동일 직무(의류MD·패션MD·의류기획MD·패션온라인MD) + **인접 직무까지 포함**(상품기획MD, 바잉MD, VMD, 온라인마케팅 등)
- 요약·공통점 분석은 이번 단계에 포함하지 않음 — 원본 데이터를 모아두면 나중에 그때그때 "이 데이터에서 공통점 찾아줘" 식으로 별도 요청할 예정
- 결과물 형태: **엑셀 파일 + 브리핑 페이지 내 '수집된 원본 데이터' 탭 둘 다** 제공

## 7. 최종 산출물 아키텍처

1. **친구가 보는 화면**: 링크 하나로 여는 웹페이지 (claude.ai 아티팩트로 게시, 이미 뼈대 버전 게시해둠)
   - 섹션 1 (트랙 A): 오늘의 맞춤 채용공고 (회사명/제목/마감일/지원링크) — 접속·요청 시점에 갱신
   - 섹션 2 (트랙 B): 수집된 원본 데이터 (회사별 자격요건/우대사항/업무내용 원문 테이블)
2. **실행 방식**: 정해진 시각의 자동 스케줄이 필수는 아니고, 트리거(접속/버튼/사용자 요청) 시점에 실행
   - 중요 제약: 클라우드 작업 환경은 외부 사이트로 직접 인터넷 요청을 못 보내므로, 실제 API/페이지 호출은 **회원님 컴퓨터가 켜져 있고 Claude 앱이 실행 중일 때**만 가능함
3. **트랙 B 산출물**: 엑셀 파일(다운로드용) + 브리핑 페이지 내 원본 데이터 탭, 두 가지 형태 모두 제공
4. **비용/유지보수**: API 중심이라 유지보수 부담 적음. 잡코리아처럼 페이지를 직접 읽는 부분은 사이트 구조 변경 시 깨질 수 있음
